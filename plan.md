# Plan: Fix Kokoro TTS Audio Quality Issue on Mobile

## Context

The FreeTTS app works correctly on desktop but Kokoro TTS produces buzzing and high-pitched noise on mobile devices. The app creates audio chunks as independent `<audio>` elements and plays them sequentially. The audio is generated by a Web Worker using `kokoro-js` and streamed as Blob objects.

## Decisions

- **Keyboard Chord**: Use `<ctrl+Enter>`
- **Mobile Kokoro Disable**: Disable the option on mobile devices
- **Kokoro Card Shrinking**: 200px card height is acceptable. Optimize the vertical space for the entire page so that it fits comfortably on a portrait 1080x1920px and landscape (1920x1080) display.
- **Kokoro Chunk Card Text Truncation**: Use text truncation for long chunk labels.
- **Mobile Kokoro UX Messaging**: Show a small info icon on the disabled button to indicate why it's disabled.
- **Speed Slider Granularity**: Use 5% (0.05) step granularity.

## Further Considerations

- **Responsive Layout**: Ensure the entire page layout (including Reveal Codes/Visual mode containers) adapts properly for mobile portrait and landscape orientations.
- **Touch Targets**: Verify all interactive elements have adequate touch target sizes (minimum 44x44px) for mobile users.
- **Performance**: Monitor memory usage when handling multiple audio elements on mobile devices with limited RAM.
- **Battery Impact**: Audio playback and preloading strategies should consider battery life on mobile devices.
- **Accessibility**: Ensure proper ARIA labels and screen reader support for audio controls, especially when cards are truncated.

## Root Cause Analysis

### Primary Issue: Autoplay Policy Violation on Mobile

Mobile browsers (especially iOS Safari) have strict autoplay policies that block audio playback without explicit user interaction. The current implementation attempts to play audio elements immediately after they're created, which:

1. **Triggers autoplay blocking** - Mobile browsers prevent audio from playing without user gesture
2. **Causes audio initialization issues** - Audio elements that can't start playing properly may produce degraded audio quality (buzzing, high-pitched noise)
3. **Creates race conditions** - The `_playChunk()` method tries to play without waiting for the audio to fully initialize

### Secondary Issue: Missing Audio Element Attributes

The audio elements lack critical attributes for mobile compatibility:
- `preload` - Mobile browsers benefit from preloading audio to ensure smooth playback
- `muted` - Required for autoplay to work on many mobile browsers
- `playsinline` - Required for iOS Safari to play inline (not fullscreen)

## Implementation Plan

### Phase 1: Add Audio Element Attributes (Critical Fix)

**File: `src/kokoro-player.js`

In `_createChunkCard()` method (line 243-247):

```javascript
const audioEl = document.createElement('audio');
audioEl.setAttribute('data-chunk', index);
audioEl.src = URL.createObjectURL(chunk.audio);
audioEl.controls = true;
audioEl.className = 'w-full mt-1';
```

**Change to:**

```javascript
const audioEl = document.createElement('audio');
audioEl.setAttribute('data-chunk', index);
audioEl.src = URL.createObjectURL(chunk.audio);
audioEl.controls = true;
audioEl.playsInline = true;  // iOS Safari: play inline, not fullscreen
audioEl.preload = 'auto';     // Preload for better mobile playback quality
audioEl.muted = true;          // Required for autoplay to work on many mobile browsers
audioEl.className = 'w-full mt-1';
```

### Phase 2: Modify Playback Logic

**File: `src/kokoro-player.js`

In `_playChunk()` method (line 284-291):

**Current:**
```javascript
_playChunk(index) {
    const container = document.getElementById(this.containerId);
    if (!container) return;
    const audioEl = container.querySelector(`audio[data-chunk="${index}"]`);
    if (!audioEl) return;
    audioEl.currentTime = 0;
    audioEl.play().catch(() => {});
}
```

**Change to:**
```javascript
_playChunk(index) {
    const container = document.getElementById(this.containerId);
    if (!container) return;
    const audioEl = container.querySelector(`audio[data-chunk="${index}"]`);
    if (!audioEl) return;
    audioEl.currentTime = 0;
    // Unmute the audio (it was muted for autoplay compatibility)
    audioEl.muted = false;
    // Small delay to ensure audio is fully initialized before playing
    setTimeout(() => {
        audioEl.play().catch(() => {});
    }, 100);
}
```

### Phase 3: Add User Gesture Tracking (Optional Enhancement)

**File: `src/FreeTtsUtils.js`

Add a flag to track when the user has interacted with the page:

```javascript
let userHasInteracted = false;

// In the main script initialization:
document.addEventListener('click', () => { userHasInteracted = true; }, { once: true });
document.addEventListener('touchstart', () => { userHasInteracted = true; }, { once: true });
```

Then in `_playChunk()`:
```javascript
audioEl.muted = !userHasInteracted;  // Only unmute if user hasn't interacted yet
```

## Verification Plan

### Desktop Verification
1. Test existing functionality is preserved
2. Verify audio plays correctly in both Reveal Codes and Visual modes
3. Test chunk clicking and auto-advance

### Mobile Verification (iOS Safari + Android Chrome)
1. **Audio Quality Check**: Verify no buzzing or high-pitched noise
2. **Autoplay Test**: Audio should start playing after initial user interaction
3. **Playback Test**: Test play/stop/pause cycles
4. **Chunk Navigation**: Click different chunks to verify seeking works

### Edge Cases
1. **Multiple rapid play/stop cycles** - Verify no audio glitches
2. **App backgrounding** - Resume playback after returning to app
3. **Low memory conditions** - Verify audio elements are properly cleaned up

## Alternative Approaches Considered

1. **Web Audio API**: Would provide more control but requires significant refactoring
2. **AudioContext resume**: Could work but adds complexity
3. **User gesture tracking only**: The `muted` and `playsinline` attributes are more critical

## Risk Assessment

- **Low risk**: Adding `preload`, `muted`, and `playsinline` attributes is standard practice
- **Low risk**: Small delay before play is harmless and improves compatibility
- **Unknown**: The exact audio format from `kokoro-js` - if issues persist, may need format conversion

## Files to Modify

1. `src/kokoro-player.js` - Audio element initialization and playback logic
2. Potentially `src/FreeTtsUtils.js` - If user gesture tracking is implemented

## Expected Outcome

After implementing these changes:
- Audio will play correctly on mobile devices
- Audio quality should be consistent across platforms (no buzzing/noise)
- Autoplay will work after initial user interaction
- No regressions on desktop functionality
